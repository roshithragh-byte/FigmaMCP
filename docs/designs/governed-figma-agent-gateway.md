## Problem Statement
Autonomous coding agents (Claude Code, Devin, custom PR review bots) operating in headless environments (GitHub Actions, container sandboxes, Cloud Run) cannot use Figma's official remote MCP server due to mandatory interactive browser OAuth and allowlisted client constraints. Consequently, engineering teams either revert to manual developer laptop workflows or duct-tape shared Personal Access Tokens (PATs) into CI secrets, triggering InfoSec exposure, severe 429 rate limits, and massive LLM context blowouts on raw node JSON trees.

## Demand Evidence
- Current state is Pre-product with architectural validation in headless agent pipelines.
- External validation hypothesis: Staff Platform / DevEx Engineers are actively blocked from rolling out autonomous design-to-code CI bots because InfoSec prohibits un-scoped, long-lived account PATs in CI runners, and parallel PR runs trip Figma's Tier 1 rate limits (10-20 req/min).

## Status Quo & Workaround Costs
1. **Shared Account PATs**: High blast radius (un-scoped access to all company files and write permissions).
2. **Rate Limit Wall**: Parallel jobs hitting raw `/v1/files` or `/v1/images` trigger `429 Too Many Requests` without structured backoff, causing CI jobs to fail flakily.
3. **Payload Bloat**: Raw Figma document trees contain thousands of lines of absolute vector/layout data, wasting tokens and confusing agent reasoning.
4. **Human Bottleneck**: Many teams simply abandon headless automation, forcing frontend engineers to pull Figma context locally on their laptops.

## Target User & Narrowest Wedge
- **Buyer**: Staff Platform Engineer / Head of Developer Experience at mid-to-large product companies.
- **Success/Failure Metric**: Promoted for accelerating engineering AI velocity; fired for security incidents or leaked tokens.
- **Narrowest Wedge**: A hosted or containerized **Governed Figma Agent Gateway**:
  - **Scoped Authentication**: Single upstream Figma Plan/PAT credential in Secret Manager; short-lived, repo-scoped bearer tokens for CI runners.
  - **Read-Only Policy Enforcer**: Strips comment/variable write mutations to prevent rogue agent edits.
  - **AST Pruning & Compaction**: Compacts raw node trees down to clean semantic component structures (<10% of raw payload size).
  - **Rate-Limit Shield & Cache**: Transparently caches frame trees and image renders across parallel PR runs, parsing and honoring `Retry-After`.

## Premises
1. A raw 1:1 remote MCP wrapper around Figma's REST endpoints has near-zero moat and little enterprise appeal because Figma already provides basic remote APIs and tokens. The real commercial product is a Governed MCP Gateway.
2. The economic buyer is the Staff Platform / DevEx Engineer managing CI/agent security and reliability, not the individual frontend developer.
3. Customer validation with 2-3 platform leads precedes enterprise multi-tenancy implementation.

## Approaches Considered
- **Approach A (Minimal Viable Headless Bridge)**: Polish open-source Cloud Run server as-is. *Rejected: Leaves rate limits and security exposure unaddressed; zero monetization moat.*
- **Approach B (Governed Figma Agent Gateway)**: **Selected.** Implement AST compaction, rate-limit caching, and read-only policy enforcement.
- **Approach C (Full Design-to-Code Verification Engine)**: *Rejected: Competing directly with Percy/Chromatic; too broad for pre-product wedge.*

## Recommended Approach: Approach B
Build the Governed Gateway on top of FastMCP:
1. Fix test and typing discrepancies in the existing FastMCP/Starlette setup.
2. Implement AST compaction utility reducing node JSON footprint.
3. Add in-memory/Redis caching layer for Figma responses and exported images.
4. Add strict read-only mode flag (`FIGMA_READ_ONLY=true`).
5. Conduct outreach to 3 Platform/DevEx leads.

## Success Criteria
- 10x reduction in LLM token consumption for Figma node inspection.
- 0 rate-limit failures across concurrent CI job runs via response caching.
- Validation conversations completed with 3 Staff Platform Engineers.
